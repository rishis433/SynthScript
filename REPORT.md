# REPORT.md

## 1. Architecture
SynthScript is built as a single-process Python CLI application, chosen because Python sits at the intersection of robust AI SDKs, automation frameworks like Playwright, and computer vision tooling. A distributed, queue-based microservice architecture was deliberately avoided; while suitable for production scale, it introduces premature complexity for validating the core loop. The system uses GPT-4o for the Discovery Phase, fed a unified Spatial Semantic Tree alongside a redacted screenshot to ensure it does not rely on a clean HTML DOM. For the target application, we built a local, intentionally hostile mock web app featuring iframes, nested tables, and no test IDs. This proxy allows us to safely test PII redaction without exposing real data, avoid rate limits, and deterministically inject runtime failures to evaluate the system's error handling.

## 2. Artifact Schema
The artifact is a strongly typed, versioned JSON file structured to decouple the probabilistic LLM discovery from the deterministic production runtime. It contains a contract block that defines typed input parameters and expected outputs, making the artifact an invocable, reusable capability for upstream AI agents. The flow section is an ordered array of action steps where each step contains a pure action, input bindings, and cascading locators, stripping away any raw LLM reasoning. Finally, a business exceptions block maps expected UI states to structured return codes, ensuring the Replay Engine can anticipate and handle known application behaviors.

## 3. Determinism & Error Handling
Determinism is achieved by strictly removing the LLM from the replay execution path, relying instead on a state machine that uses a cascading locator strategy to handle minor UI drift. For each target, the engine attempts to resolve via an Accessibility ID first, falls back to OCR-relative positioning if that fails, and finally attempts visual template matching. The engine categorizes runtime interruptions into a strict taxonomy. Expected business outcomes, such as a "No records found" message, are checked against the artifact's exceptions and gracefully returned as a successful business execution, not a crash. Recoverable conditions trigger global interceptors that dismiss known generic popups and retry the step, while hard failures cause the engine to halt, capture a DOM snapshot and screenshot, and return a strict failure payload for debugging.

## 4. Heterogeneity & Scale
To extend beyond web apps to legacy thick-clients or Citrix desktops, the architecture relies on a Surface Adapter base class. The JSON artifact dictates what needs to be done, while the adapter dictates how, allowing the web adapter to be swapped for an OS-level adapter without changing the core Replay Engine logic. To address multi-tenant scale where hundreds of institutions run slightly modified versions of the same vendor software, SynthScript utilizes a layered artifact strategy. A base artifact is recorded on the vanilla application, and tenant-specific UI modifications are handled via a delta patch, allowing the system to compile the two at runtime rather than recording hundreds of distinct artifacts.

## 5. Escalation & Handoff
When the Replay Engine encounters a hard failure or an unauthorized risky action, it initiates a Human-in-the-Loop handoff by halting execution but explicitly keeping the live browser context alive and frozen. The engine emits an intervention request with the current screenshot and step context. The human operator then takes control of the live session to interact directly with the frozen DOM and resolve the blocker, while a background daemon logs these manual interventions. Once the operator hands control back, the Replay Engine captures a fresh state of the screen, dynamically re-orients itself to the new UI, and seamlessly continues the remaining steps in the artifact.

## 6. Safety
Because this system operates on regulated financial data, it utilizes a strict policy engine constrained by an allowlist of permitted domains and internal IP routes. Elements mapped to destructive roles require explicit programmatic authorization to execute; without it, the engine treats the step as a hard failure and escalates to a human. To protect sensitive information, a local proxy redacts fields like Social Security Numbers and account balances from the accessibility tree and draws black bounding boxes over the raw screenshot before the payload is ever sent to the LLM during the discovery phase. The primary limitation of this model is that local redaction is imperfect, and highly obfuscated text might bypass the OCR redactor.

## 7. Cuts
Several features were deliberately left out to focus strictly on the load-bearing components of the system, including a fully functional remote operator console, multi-tenant message queues, and a desktop application adapter. With more time, the next step would be to build an agent-facing capability registry that exposes the saved JSON artifacts as standard tool-calling schemas, allowing an upstream conversational agent to dynamically discover and invoke legacy capabilities as if they were modern APIs. I would also implement multi-run stability scoring to calculate a flakiness metric for newly generated artifacts before they are approved for unattended production execution.
